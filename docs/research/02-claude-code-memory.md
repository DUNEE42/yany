# Claude Code 记忆机制研究

日期：2026-11-25  
官方来源：

- <https://code.claude.com/docs/en/memory>
- <https://code.claude.com/docs/en/common-workflows>

## 结论先行

Claude Code 把跨会话知识分成两种完全不同的东西：

1. **用户写的稳定指令**：`CLAUDE.md` / `AGENTS.md` / rules。
2. **Claude 自己积累的工作记忆**：auto memory。

两者都不是系统提示词里的不可违抗规则，而是会话开始时注入的上下文。官方文档明确说，
它们不是强制配置；要机械阻止某种动作，应使用 hook。

对言语最值得吸收的是“索引常驻、详情按需读取”：

- 常驻上下文的是一份短索引，不是所有记忆正文。
- 详细主题文件只在需要时打开。
- 自动记忆可以关闭、审阅、编辑和删除。
- 记忆是按会话/项目隔离的，不会无边界地跨所有上下文扩散。

## Claude Code 的公开行为

### CLAUDE.md

官方文档把 `CLAUDE.md` 定位为用户主动编写的持久项目说明，适合：

- 构建命令、代码规范、目录结构。
- “总是这样”“不要这样做”的稳定规则。
- 用户反复纠正过的内容。
- 新成员也需要知道的背景。

它不适合多步骤流程或只对局部分支有效的信息；这些应放进 skill 或路径作用域规则。

### Auto memory

官方文档对 auto memory 的事实描述：

- Claude 根据用户的纠正和偏好自己写笔记。
- 作用域是每个仓库/项目，同一仓库的 worktree 与子目录共享。
- 默认存放在 `~/.claude/projects/<project>/memory/`，本机保存。
- 目录里有一个 `MEMORY.md` 索引，以及多个主题文件。
- 会话开始时，只加载 `MEMORY.md` 的前 200 行或 25 KB，先到者为准。
- 主题文件不会在启动时加载，Claude 需要时再按文件工具读取。
- 索引接近上限时会提示合并、缩短或删除陈旧条目；超过上限后，超出部分不会进入下一次上下文。
- 文件有 YAML frontmatter 时，会记录 ISO 8601 修改时间。
- `/memory` 可以浏览、打开、编辑和删除记忆，也能开关 auto memory。
- 旧会话记录会按清理周期删除，但 memory 目录不参与这个自动清理。

这些机制解决的不是“存得更多”，而是“索引可读、详情可追溯、上下文有硬预算”。

### 会话

官方文档说明每个 Claude Code 会话都从新的上下文窗口开始；跨会话连续性由
`CLAUDE.md`、auto memory 和会话恢复机制承担，而不是假设模型自身永远记得上一段聊天。

## 对言语的取舍

### 应该吸收

| Claude Code 机制 | 言语映射 |
| --- | --- |
| `CLAUDE.md` 是用户明确写的稳定指令 | 言语的固定边界、稳定偏好单独存储，不能靠 AI 推测 |
| 每会话从空上下文开始 | 不把历史无限塞给模型；用短期摘要和相关记忆重建当前上下文 |
| `MEMORY.md` 是短索引 | 言语画像和检索结果保持精简，完整来源留在本地 |
| 主题文件按需读取 | v1 先按关键词取少量原子记忆；规模变大再做索引/向量检索 |
| `/memory` 可审阅编辑 | 记忆页支持确认、拒绝、编辑、删除和批量清理 |
| 索引有 200 行/25 KB 硬预算 | 言语画像 600 字符、短期摘要 800 字、长期记忆 2000 字符 |
| 记忆按项目隔离 | 言语记忆必须按 companion/会话隔离，不能跨角色串味 |
| 记忆是上下文而非强制规则 | 当前用户请求、安全和固定边界高于记忆资料 |

### 不应照搬

- Claude Code 的 auto memory 面向编码任务，用户偏好和项目事实可以混在一起；
  言语必须拒绝 AI 自我说明和一次性知识问答。
- Claude Code 允许模型自行修改多个 markdown 主题文件；言语不应让模型直接改写用户画像，
  只允许模型生成候选，再由本地确定性策略决定状态。
- Claude Code 的索引是 25 KB 级别；言语每轮上下文更小，不能把完整索引塞进去。
- 编码 Agent 的“任务进度”不是陪伴产品的人格或情绪；两者不能共用同一晋升门槛。

## 对言语当前实现的验证

当前 1.6.1 的改造与该机制一致：

- 原始消息仍是唯一事实源，摘要和长期记忆都是派生数据。
- 短期摘要只保留近期事件、当前状态和未完成话题。
- 稳定偏好、边界和事实由本地策略自动晋升；其余进入候选或丢弃。
- 输入上下文的长期记忆有数量和字符预算。
- 用户可查看、修改、拒绝、删除、清空和关闭自动记忆。
- 记忆页按“已生效 / 待确认 / 近期经历 / 已过期”分组。

仍需在后续版本验证：

- 大量记忆时，索引摘要是否仍能控制在目标预算内。
- 用户长期使用的记忆量是否达到引入本地 embedding 的门槛。
- 来源删除、摘要重建和跨会话隔离的压力测试。
