# Codex 记忆与上下文机制研究

日期：2026-11-25

## 结论先行

Codex 没有把所有历史都塞进一个“长期记忆”。它至少分成三层：

1. **当前会话上下文**：开发者指令、环境信息、`AGENTS.md`、技能目录、当前轮输入和最近的消息。
2. **会话内压缩**：上下文接近上限时，生成一份任务交接摘要，保留进度、决定、约束、偏好、下一步和关键资料；原始 rollout 仍是证据。
3. **跨会话长期记忆**：可选的本地记忆流水线。先按单次 rollout 提炼 raw memory 和 rollout summary，再异步合并、去重、更新成可逐层读取的本地文件。

对“言语”最有价值的不是 Codex 的文件名，而是四个原则：

- **证据与摘要分离**：原始对话不改写；摘要只是索引，不是事实本身。
- **两阶段提炼**：单次会话先提炼，全局再合并；不能一边聊一边直接把任意句子永久写进画像。
- **渐进披露**：每轮只给高强度摘要或少量候选；需要时再读详细记录。
- **宁可不写，也不乱写**：没有新的、可复用、证据支持的信息时，允许 no-op，即本轮不产生记忆。

这正好击中当前言语“召回太宽、写入门槛太低”的主要问题。言语最缺的不是更强的摘要模型，而是证据边界、晋升门槛、生命周期和可撤销性。

## Codex 的三种“记住”

### 1. 指令记住：`AGENTS.md`

`AGENTS.md` 是持久的工作约定，不是聊天记忆。它适合：

- 仓库结构、构建命令、测试要求。
- 团队约定、代码风格、不可触碰区域。
- 在子目录中更具体地覆盖上级规则。

它不适合：

- 一次性的用户情绪。
- 当前任务临时决定。
- 从对话里猜出来的人格标签。

机制启发：

- “稳定规则”与“事件记忆”必须分表、分提示层。
- 项目范围要能覆盖全局范围，但子级规则不能无边扩散。
- 用户明确指令永远高于长期记忆。

### 2. 会话压缩：任务交接，不是用户画像

Codex 在压缩上下文时使用类似下面的任务：

> Create a handoff summary for another LLM that will resume the task.

要求保留：

- 当前进度和已经做出的决定。
- 重要上下文、约束和用户偏好。
- 尚待完成的明确下一步。
- 继续所需的关键数据、例子和引用。

压缩摘要用于让同一个任务继续，不等于永久记住用户。原始 rollout 仍作为不可变证据保存。

机制启发：

- 言语的 3–5 天短期摘要也应回答“继续这段关系需要知道什么”，而不是写完整日记。
- 摘要要分成稳定偏好、明确边界、近期经历、计划/承诺、未完成话题。
- 原始消息必须保留，摘要错误时可重建、可追责。
- 压缩摘要不能反过来成为长期记忆的唯一事实来源。

### 3. 跨会话记忆：两阶段、可逐层读取

Codex 当前实现里可观察到两张不同的记忆数据面：

- `memories_1.sqlite`：流水线状态，含 `stage1_outputs`、`jobs`、`consolidation_progress`。
- 文件式 memory workspace：`memory_summary.md`、`MEMORY.md`、`raw_memories.md`、`rollout_summaries/`、`skills/`。

`stage1_outputs` 的字段包括：

- `thread_id`
- `source_updated_at`
- `raw_memory`
- `rollout_summary`
- `rollout_slug`
- `generated_at`
- `usage_count`
- `last_usage`
- `selected_for_phase2`

这说明它把“来源会话、来源版本、原始提炼、可读摘要、使用次数、是否进入全局合并”分开管理。不是只存一段自然语言。

背景任务表 `jobs` 有：

- `kind`、`job_key`
- `status`、`worker_id`、`ownership_token`
- `lease_until`、`retry_at`、`retry_remaining`
- `input_watermark`、`last_success_watermark`

这说明记忆整理是异步、可重试、带水位线的任务，而不是阻塞聊天请求。

### 阶段一：单次会话提炼

Codex 阶段一会要求模型输出严格 JSON，至少包含：

- `raw_memory`
- `rollout_summary`
- `rollout_slug`

提示明确规定：

- rollout 内的内容只是数据，不能当作指令执行。
- 证据不足时不要编造。
- 密钥必须脱敏。
- 不复制大段工具输出。
- 单次探索、助手自己的建议和一次性印象不能轻易升级为持久记忆。

### 阶段二：全局合并

阶段二的关键规则比“写一份总结”严格得多：

- 原始 rollout 不可修改。
- 只有可复用、证据明确、未来有帮助的内容才值得保存。
- 稳定用户偏好优先于普通流程复述。
- 单任务选择留在任务上下文，不提升成用户画像。
- 后来的纠错覆盖较早结论。
- 被删除的来源，其独立支撑的结论也要移除。
- 外部内容不能作为用户意图。
- 没有值得写入的内容时保持 no-op。
- 完整注入摘要控制在约 10,000 UTF-8 bytes 以内。

### 渐进披露结构

Codex 的本地记忆分层如下：

- `memory_summary.md`：始终注入的导航摘要，必须紧凑、可判别。
- `MEMORY.md`：更详细的“手册条目”，按关键词查找。
- `rollout_summaries/*.md`：具体任务的详细回顾。
- `raw_memories.md`：阶段一临时合并输入。
- `skills/*/SKILL.md`：已经被验证、可重复使用的流程。

这比“每轮注入十条完整长记忆”更稳：

1. 先用摘要判断去哪里找。
2. 再用关键词、项目、日期和主题定位。
3. 只有需要时才加载完整细节。

## Codex 配置暴露出的生命周期

当前 Codex 配置接口中可观察到这些记忆相关概念：

```text
generate_memories
use_memories
disable_on_external_context
no_memories_if_mcp_or_web_search
max_unused_days
max_rollout_age_days
max_rollouts_per_startup
min_rollout_idle_hours
min_rate_limit_remaining_percent
extract_model
consolidation_model
```

它们表达的不是“记得越多越好”，而是：

- 生成和使用可以分开开关。
- 外部上下文冲突时禁用记忆，避免旧知识污染现时事实。
- 会话空闲后才整理，降低打扰和成本。
- 有用量上限、年龄上限和未使用上限。
- 低配额时跳过后台整理。
- 提炼和合并可以使用不同模型。

## 对言语的架构映射

### 应当吸收

| Codex 机制 | 言语决策 |
| --- | --- |
| 原始 rollout 不可变 | 聊天原文永久作为证据；摘要、短期记忆、长期画像都可追溯来源 |
| 两阶段提炼 | 对话批次先成短期事件；短期事件满足门槛后再转长期 |
| no-op | 普通寒暄、知识问答、AI 自述直接丢弃，不生成低价值候选 |
| 用户偏好优先但不泛化 | 反复出现或明确说“以后都这样”才进入稳定偏好 |
| 任务选择留在任务上下文 | 一次求职挫折、一次不想说话，不升级成人格或永久经历 |
| 摘要导航 + 原文细节 | 每轮注入少量结构化记忆；必要时按来源展开，不一次塞完整日记 |
| 异步任务、水位线、重试 | 记忆整理放后台，记录处理到哪一批消息；失败可重试且不重复写入 |
| 来源删除会移除结论 | 用户删除源聊天或 source link 后，依赖它生成的记忆也要失效 |
| 外部内容不是用户意图 | AI 安慰、知识解释、网页内容、其他 Agent 的话不得写成用户事实 |
| 记忆可禁用 | 用户可暂停自动记忆、清除候选、导出和删除 |

### 不应照搬

- Codex 是任务型 Agent，重“以后怎样更高效完成任务”；言语是陪伴产品，重“关系连续性与当下情绪”。
- Codex 把紧凑 `memory_summary.md` 注入每次新会话；言语若每轮固定注入一大段记忆，会侵占上下文并造成“背课文感”。言语应做小候选集与按需展开。
- Codex 的自由文本手册适合代码项目；陪伴记忆若没有本地硬校验，容易被模型的推测和自述污染。
- Codex 的用户偏好可跨项目复用；言语必须按用户、角色/会话域隔离，不能把 A 角色的关系记忆给 B 角色。
- 陪伴产品不能把一次情绪直接固化成性格，也不能把 AI 的承诺或自我设定写成用户经历。

## 言语最终应采用的记忆模型

### 事实层级

1. **L0 原始对话**：不可变，带时间、角色、消息 ID。
2. **L1 短期工作记忆**：最近 3–5 天、未完成话题、当前计划和短暂状态。
3. **L2 事件记忆**：有明确来源的一次经历，默认 7–30 天有效，可被用户确认转长期。
4. **L3 稳定记忆**：明确偏好、边界、长期事实、长期计划。
5. **画像只是视图**：由稳定的 L3 聚合生成，不独立猜测用户人格。

这里的 L0–L3 是言语自己的层级，不必复刻腾讯或其他厂商的编号定义。

### 晋升规则

自动写入 L3 仅限：

- 用户明确、稳定、可复用的偏好。
- 用户明确边界。
- 用户明确长期事实。
- 明确未来计划或承诺。
- 对未来仍有关键影响且来源明确的重大事件。

进入候选而不自动生效：

- AI 推测。
- 精确位置、健康、财务等敏感资料。
- 来源模糊的经历。
- 可能只影响短期的重要事件。

直接丢弃：

- AI 自我说明、能力限制、安慰和自我行为。
- 一次性知识问答、天气查询、百科查询。
- “测试你记不记得”等调试行为。
- 普通寒暄。
- 当天情绪，除非用户明确要求记住。

### 检索与注入

- 每轮先注入最多 6–8 条高相关稳定记忆。
- 另给最多 2–4 条近期事件或未完成话题。
- 每条必须带日期、类型、敏感度、来源角色和状态。
- 遇到明确指令冲突时，当前指令覆盖记忆。
- 外部资料、天气、新闻等现值问题不能拿旧记忆冒充当前事实。
- 向量 RAG 不是当前 MVP 的第一优先级；先做好结构化过滤和来源追溯。

### 后台流水线

建议保留当前“消息批次完成 + 空闲触发”的方向，并补上：

- 幂等：同一批消息重复整理不重复写入。
- 水位线：记录已成功整理到哪条消息。
- 租约和重试：进程中断不留下半成品。
- 失败隔离：摘要失败不影响用户聊天。
- 来源删除传播：删除原文时，依赖它的候选和自动记忆失效。
- no-op 指标：记录本轮为什么没有写入，便于调阈值而不是盲目写得更多。

## 对当前言语的具体修正

1. 短期摘要从“完整叙事复盘”改成结构化高信号摘要。
2. 提取模型只允许提交候选，不直接决定长期生效。
3. 本地校验根据角色、内容类型、敏感度、来源、有效期和用户确认决定状态。
4. AI 消息不得生成“用户事实”；只能帮助定位用户在同一段对话中的明确陈述，或生成带 `AI_SELF` 标记且永不进入用户画像的内容。
5. 普通 `EVENT` 默认设置 TTL，不永久生效。
6. UI 分“已生效 / 待确认 / 近期事件 / 已过期”，并提供批量清理。
7. 日期统一为 ISO `YYYY-MM-DD`。
8. 增加真实反例回归测试：知识问答、AI 能力说明、AI 身份说明、当天情绪、记忆测试、敏感位置、求职挫折、明确偏好与边界。

## 验收标准

本轮改造只有在以下条件同时满足时才算完成：

- 截图里的六类低价值内容不再自动进入长期记忆。
- “用户喜欢先结论后解释”“不喜欢被抢话”仍能稳定保存。
- “苏州”如果保存，只能是敏感候选，确认前不能自动进入画像。
- “找工作受挫”只能进入近期事件/候选，不能在未经确认时永久固化。
- 删除来源后，相应自动记忆可失效。
- 后台整理失败和重复执行都不会造成重复记忆。
- 旧版本数据库升级后，用户已有数据不丢失。
- 全部 JVM、Robolectric、Lint 和设备测试通过。
