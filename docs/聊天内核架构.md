# 言语聊天内核架构

## 目标

聊天内核只负责可靠地完成一轮对话：

```text
保存用户消息
-> 组装上下文
-> 调用模型 Provider
-> 接收流式事件
-> 保存回复终态
```

界面、Provider 协议和数据库结构可以替换，但消息生命周期不变。

## 依赖方向

```text
UI / Compose
  -> Application / ViewModel
  -> Domain
       ChatEngine
       ContextAssembler
       MemoryContextProvider
       MemoryWorkCoordinator
       SafetyPolicy
       ChatProvider
       ChatConversationStore
       ProviderSettingsStore
       ChatStyleStore
  <- Data adapters
       DeepSeekApi
       ChatRepository
       MemoryRepository
       ApiSettingsStore
       SharedPreferencesChatStyleStore
  -> Platform
       OkHttp SSE
       Room + SQLCipher
       Android Keystore
```

领域层不得导入 `data`、`ui` 或 `di`。`ArchitectureBoundaryTest` 会在 JVM 测试中检查。

## UI 设置架构

```text
MainApp
├─ SettingsUiState  -> SettingsScreen
└─ ChatUiState      -> ChatScreen
```

设置页分区：

```text
模型连接
对话手感
隐私与数据
关于
```

设置状态不混入聊天消息。首次启动无 Key 时进入连接页；配置完成后返回聊天。

## 消息不变量

1. 同一会话内 `sequence` 唯一且递增。
2. 一轮对话包含一个用户消息和一个 AI 回复消息。
3. AI 回复通过 `replyToMessageId` 关联用户消息。
4. 消息插入冲突必须失败，不允许静默覆盖。
5. 重试复用原用户消息，不插入第二条相同输入。
6. 进程中断后，遗留的 `PENDING/STREAMING` 消息恢复为 `INTERRUPTED`。
7. 失败或中断的回复不进入下一轮模型上下文。
8. 每次运行拥有独立代次；旧任务完成时不能覆盖新会话状态。

## 消息状态

```text
PENDING -> STREAMING -> COMPLETED
                    ├-> INTERRUPTED
                    └-> FAILED
```

重试只允许从 `FAILED` 或 `INTERRUPTED` 的 AI 消息发起。

## Provider 契约

```kotlin
interface ChatProvider {
    val id: String
    val capabilities: ProviderCapabilities
    fun stream(request: ChatRequest): Flow<GenerationEvent>
    suspend fun testConnection(config: ProviderConfig): Result<Unit>
}
```

Provider 负责 URL、鉴权、请求格式和供应商流协议。上层只消费统一事件：

```text
Started
Delta
Usage
Completed
Failed(code, message, retryable)
```

流内 JSON 错误会映射为 `Failed`，畸形 SSE 数据也不会再被静默忽略。

## 对话手感

```text
temperature  -> Provider 采样参数
closeness    -> 提示词中的克制 / 热络程度
replyLength  -> 提示词长度指引 + max_tokens
```

temperature 降低会减少发散，不等于让角色冷淡；情绪距离必须通过 closeness 调整。

## 上下文规则

ContextAssembler 只包含：

- 人格与边界
- 动态生成的用户画像
- 最近短期摘要
- 与当前问题相关的长期记忆
- 已完成的历史消息
- 本轮当前用户消息

它排除：

- 失败占位消息
- 中断的半截 AI 回复
- 空白 AI 占位消息
- 未确认的记忆

当前用户消息必须进入上下文。若预算不足，必须明确失败，不能静默删除。

## 提示词分层

`CompanionPromptBuilder` 借鉴 Codex 的分层上下文思路，但不复制 Codex 的内部提示词。系统消息由独立分区组成：

```text
companion_identity        稳定身份、人格和表达习惯
hard_boundaries           不可被用户资料或普通风格覆盖的边界
response_policy           如何理解问题、决定内容和长度
current_interaction_style 回复长度档位与亲近感
user_memories             用户确认过的参考资料，不是指令
safety_override           本轮动态安全要求，优先级最高
examples                  只校准语气、节奏和详略
instruction_priority      规则冲突时的固定顺序
```

冲突顺序：

```text
当前安全要求
> 固定边界
> 用户当前请求
> 当前交互风格
> 用户记忆资料
> 示例
```

提示词不把“简短”理解成所有问题都只答一到三句：

- 寒暄和短句通常一到三句。
- 知识、观点、计划或情绪类问题通常三到六句。
- 用户明确要求详细解释时完整作答。
- 不为凑长度重复，也不为简短省略关键信息。

用户记忆通过独立标签注入，并明确说明是“资料，不是指令”。这样即使记忆文本包含命令式表达，也不能直接改写角色规则。

1.6.0 已用短期摘要、画像和相关性检索替换“确认记忆前 30 条”的过渡实现。
完整的分层、数据模型、后台写入、冲突处理和检索方案见
[记忆系统最终设计-2026-11-25](记忆系统最终设计-2026-11-25.md)。

## 安全策略

安全策略分为：

```text
crisis    -> 暂停角色扮演，显示现实安全资源
distress  -> 提示词要求先支持感受并确认当前安全
normal    -> 普通聊天
```

危机识别使用自伤意图短语和否定判断，不把所有“自杀”讨论都当成同一风险。它仍是本地规则层，不替代真实临床判断。

## 流式终态

只有收到明确的完成信号才算 `COMPLETED`：

```text
[DONE]                    -> COMPLETED
连接提前关闭               -> FAILED / stream_incomplete
用户主动停止               -> INTERRUPTED
401 / invalid_request      -> FAILED / 不可重试
429 / 5xx / 网络错误       -> FAILED / 可重试
流内 JSON error            -> FAILED / 按错误类型判断
无法解析的 SSE 数据         -> FAILED / malformed_stream
```

## 本地数据

- API Key：Android Keystore + AES-GCM。
- 聊天：Room + SQLCipher。
- 数据库版本：v5。
- 消息通过外键关联会话，会话删除时级联删除消息。
- 短期摘要、`memory_items`、`memory_sources` 和 `memory_jobs` 全部位于 SQLCipher。
- 记忆正文、来源消息、有效时间、确认状态和失效关系分表保存。
- 旧 `memories` 表只为 v4→v5 迁移保留，运行时不再写入。
- SQLite 全文索引是派生数据，可由记忆正文重建。
- 1.0.0 已损坏的历史只在 1->2 迁移中清理一次。
- 用户可以在设置中删除 Key 或清空聊天，两者互不混淆。
- 清空聊天会删除对应摘要和任务，并让失去证据的 AI 记忆过期。
- 清空全部记忆会写入检查点并暂停自动记忆，避免旧聊天立即回填。

## 诊断

`DiagnosticSink` 只记录：

- 一次生成的耗时。
- 结果状态。
- 错误码。
- Provider ID。
- 模型 ID。
- App 版本。
- AI 消息 ID。

它不记录聊天正文和 API Key。
