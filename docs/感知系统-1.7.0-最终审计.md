# 言语 1.7.0 感知系统最终审计

日期：2026-11-25  
范围：通知感知、前台应用、粗粒度城市、天气、SearXNG、Room v6、上下文注入、UI  
结论：未发现新的 P0；仍有 2 个 P1 和 5 个 P2。

## P1-1：还不能主动在“下课时”提醒

当前通知事件可以通过以下链路进入聊天：

```text
允许通知 → 本地清洗 → Room 临时事件
→ 用户主动发消息 → 选择相关事件 → DeepSeek 回复
```

但没有任何 `WorkManager`、`AlarmManager` 或本地通知调度器。因此：

- 用户不打开聊天时，言语不会主动提醒。
- 没有课程表时，系统不知道“本节课何时结束”。
- 包裹事件可以成为聊天上下文，但尚未成为主动提醒任务。

这是功能范围缺口，不是安全漏洞。若 1.7.0 对外宣称“会在下课时提醒”，
属于过度承诺。

修复：

- 增加独立的 `ReminderRule`：事件、触发时间、来源、TTL、去重键。
- 课程结束时间必须来自用户课程表或系统日历，不得猜测。
- 使用 WorkManager/AlarmManager 调度本地通知。
- 每个包裹事件最多提醒一次，用户点击“已取件”立即取消。
- 文字生成可选调用模型，但调度规则必须本地确定性执行。

## P1-2：搜索结果仍是未经主动确认的外部指令载体

位置：

- `domain/CompanionPromptBuilder.kt:56`
- `data/search/ContentSanitizer.kt`

现状：

搜索结果会被标记为 `untrusted-data`，标签也会转义，这是正确的。但目前只做
HTML/控制字符清洗，没有检测或隔离“忽略之前指令”“泄露系统提示”等自然语言
提示词注入。

影响：恶意网页摘要仍有可能影响模型行为。由于当前只使用搜索摘要、不自动打开
全文，风险有限，但不应把“加了标签”视为完整防护。

修复：

- 过滤常见 instruction-like 片段，或在本地把结果转为高度结构化字段。
- 高风险查询只给模型标题、域名、时间和短摘要。
- 提示词明确禁止执行外部文本中的命令，并保留当前已有规则。
- 增加恶意摘要端到端测试。

## P2-1：包裹“已签收”被描述为“等待领取”

位置：

- `data/notification/NotificationParser.kt:76`

`PARCEL_ACTION` 已包含“签收”，所以代码先命中“等待领取”，永远到不了后面的
`text.contains("已签收")` 分支：

```text
包裹已签收 → 有快递或包裹到达，等待领取
```

修复：先判断“已签收/已取件”，再判断“已到/待取/领取”。

## P2-2：关闭来源后旧事件仍显示在感知页

位置：

- `ui/perception/PerceptionViewModel.kt:114`
- `domain/perception/PerceptionContextCoordinator.kt:24`

发送给模型的链路已经按当前允许列表过滤，这是正确的。但页面的事件 flow 没有按
允许列表过滤；关闭来源后，旧摘要仍在“近期观察”中显示。虽然不会进入新上下文，
但容易让用户误以为关闭没有生效。

修复：UI 只展示当前允许来源的事件，或在关闭来源时同步删除该来源事件。

## P2-3：搜索查询仍可能包含不必要的个人信息

位置：

- `domain/perception/PerceptionQueryPolicy.kt:38`
- `domain/perception/PerceptionContextCoordinator.kt:84`

当前已经能从“帮我查一下……”中提取后半段，并过滤明显私人叙事，比直接发送整句
安全很多。但姓名、学校、公司、邮箱等不一定能识别。

修复：搜索前显示将发送的查询词，首次使用或包含专有名词时要求确认；提供
“只搜索这个主题”按钮比全自动更可靠。

## P2-4：前台应用只有低精度采样

位置：

- `data/perception/AndroidForegroundAppProvider.kt:24`

当前会按 resumed/paused/stopped 更新状态并限制新鲜度，已经修复旧版“9 分钟前
的应用仍算当前”的问题。但 UsageStats 事件仍可能滞后，某些 OEM 返回不完整。

修复：Prompt 始终写“最近一次前台应用观察”，不写“你现在正在使用”，并显示
观测时间。

## P2-5：通知来源列表可能暴露用户安装/使用习惯

位置：

- `ui/perception/PerceptionScreen.kt`
- `data/local/PerceptionEntities.kt`

来源包名和最后出现时间保存在 SQLCipher 中；这是本地数据，风险低于云端，但
仍属于使用习惯。当前提供“清除来源记录”，但没有自动过期。

修复：来源记录 14–30 天无更新自动删除；页面明确说明“只展示近期出现过的
通知来源”。

## 已确认修复的部分

- API 26–28 的 `AppOpsManager` 兼容分支已加入。
- 通知权限撤销和来源关闭会在 `PerceptionContextCoordinator` 中阻止事件进入上下文。
- `GENERIC` 通知不再持久化，避免“允许应用”被解释成允许全文。
- 中文验证码边界正则已修复。
- 通知异步异常已被捕获，不会因数据库错误直接终止进程。
- 网络城市、应用名、天气和通知文本已统一转义。
- 空搜索结果不再伪装成成功查询。
- 来源引用改为 `[S1]` 形式，只附加实际引用来源。
- 当前前台应用会处理 pause/stop，并限制结果新鲜度。
- 网络城市缓存绑定网络身份。
- 搜索、天气和 IP 响应都使用有界读取。

## 建议

P1-1 是产品承诺问题：如果不实现主动调度，最终说明必须明确写成“聊天时可参考
近期通知”，不能宣称已经实现下课时主动提醒。

P1-2 应在联网搜索正式开放前补充。两个 P1 处理后，其余 P2 可以按版本节奏继续，
不阻塞本次感知能力作为“实验功能”交付。

## 交付前修复复审

最终交付代码已追加处理以下项目：

- P1-2：搜索和通知共用 `UntrustedTextPolicy`，过滤常见中英文 Prompt Injection；
  搜索恶意摘要测试覆盖。
- P2-1：包裹“已签收”优先于“等待领取”判断。
- P2-2：撤销通知权限或关闭来源后，观察页面与模型上下文同时过滤旧事件。
- P2-5：通知来源记录 30 天无更新自动删除，页面提供手动清除。
- 搜索结果只按模型实际出现的 `[S#]` 标记附加来源，未引用结果不冒充答案依据。
- 响应体按字节上限流式读取；前台应用和网络城市缓存已降低陈旧风险。

P1-1 仍作为明确的产品范围边界保留：1.7.0 是“聊天时可参考已允许的近期观察”，
不是主动定时提醒系统。最终用户文档、README 和应用内文案均未宣称会在无用户消息时
主动提醒下课取件。

P2-3 仍存在：自动搜索会屏蔽常见私人叙事和敏感字段，但中文姓名、学校、公司等
专有名词识别不是完备的。通用搜索默认关闭，只对用户配置的 SearXNG 和明确时效问题生效。
后续正式扩大搜索范围前，应增加“发送前显示/编辑查询词”的确认界面。
